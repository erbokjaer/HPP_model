# HPP_model

Simulink RMS model of a hybrid power plant (wind, PV and battery behind one point of connection) with a hierarchical control structure: an HPP controller, a plant controller per technology, and an asset controller per asset instance. Every controller is a separate model built so it can later be code-generated and wrapped as an IEEE/CIGRE DLL for PSCAD.

MATLAB R2026a with Simulink. Parallel Computing Toolbox is optional.

## Quick start

```matlab
openProject("HPP_model.prj")   % sets the path and loads the default p
runCase()                      % run the nominal case
listCaseSets()                 % show the available case sets
runSweep("grid_Pref_Pbess")    % run every case of a set
```

Or open `main.m`, pick a case set, cases, the network model (`network`) and Fast Restart (`fastRestart`) in its settings block, and press Run: it runs (or reloads) the selected cases, plots them and prints a summary table.

Always open the project first. It puts `params/`, `models/`, `scripts/` and `utilities/` on the path and sends Simulink cache files to `work/`. No script uses `cd` or `addpath`.

The architecture, interfaces, typical values and the staged plan are in [docs/design.md](docs/design.md). **Status: stage 5 of 5 started** (structure, phasor network, IEC 61400-27-1 Type 4A wind turbine, WECC REEC_B/REEC_C + REGC_A for PV and BESS, closed-loop Q control in the assets, WECC REPC_A plant controllers; the HPPC closes the P loop at the POC with ramp limit, LFSM-O / LFSM-U / FSM and SOC-aware dispatch, and a Q, voltage or power factor loop, after Energinet's DK1 requirements).

## Model structure

```
HPPC (0.1 s) ── WPPC / SPPC / BESSC (20 ms) ── N × WT / PV / BESS asset (1 ms)
                                                each asset = asset controller + generator model
wind:  turbine ─ 0.69/10 kV ─ 10 kV feeder ─ 10 kV bus ─ 10/33 kV ─┐
PV:    station ─ 0.6/33 kV ─ 33 kV feeders ─────────────────────────┤ 33 kV HPP busbar ─ 33/132 kV ─ POC ─ grid (SCR 10)
BESS:  unit ─ 0.69/33 kV ─ short 33 kV cable ───────────────────────┘
```

The network is a positive-sequence phasor (RMS) model in per unit on 180 MVA. The `Network` block in `HPP.slx` holds two models with the same results, chosen per run (see Parameters): a nodal solver, V = Z·I every step (data from `networkSolverData`, fast, the default), and a Simscape Electrical model of the same components in frequency-and-time mode (slower, component-wise). The generator models are current sources aligned with their terminal voltage of the previous step. Measurements come from the network: P, Q, V at the POC to the HPPC; each plant's P and Q where it feeds the 33 kV busbar (wind: 33 kV side of its 10/33 kV transformer) and the busbar voltage to its plant controller; terminal voltage to each asset. Typical values (transformers, cables, grid) are in `networkParameters` and `gridParameters`.

**Layout of `HPP.slx`.** The top level has six subsystems, left to right: `TSO` → `HPP controller` → `Wind plant` / `PV plant` / `BESS plant` → `Network` → `Logging`.
- **Buses** connect the subsystems. They carry SI units (W, var; voltages in pu).
- **Each subsystem converts to its controller's per-unit base** and applies the communication delays of the links it receives.
- **The controller models keep flat scalar ports** (the future DLL interface); Bus Selectors and Bus Creators sit around them.
- **The forward chain is drawn as lines**, while feedback and logging signals use colour-coded Goto/From blocks: orange = plant measurements → HPPC, green = network → plants and HPPC, grey = logging only.
- **Each signal path between control levels is one "link" block**: a small masked subsystem with its unit conversion, measurement memory and communication delay, labelled for example `to pu | mem | comm.meas_plant`.

| File | Contents |
|---|---|
| `models/HPP.slx` | Top model (layout above). **Generated by `buildHPP`; do not edit by hand**: manual changes are lost at the next build. Change the build script instead. |
| `models/ctrl/HPPC.slx` | HPP controller (future DLL) |
| `models/ctrl/WPPC.slx`, `SPPC.slx`, `BESSC.slx` | Plant controllers, asset signals as vectors of width N (future DLLs) |
| `models/ctrl/WT_ctrl.slx`, `PV_ctrl.slx`, `BESS_ctrl.slx` | Asset controllers (future DLLs) |
| `models/assets/WT_asset.slx`, `PV_asset.slx`, `BESS_asset.slx` | Asset models: one asset controller instance + converter model (IEC Type 4 generator system for wind, WECC REGC_A for PV and BESS) + battery energy for BESS |

**Who owns which model:**
- **`HPP.slx` is always generated.** `buildHPP()` rebuilds it for the layout in the parameters (asset counts `p.wt.N`, `p.pv.N`, `p.bess.N`; default 2 / 2 / 1). Never edit it by hand. `runCase` and `runSweep` stop with a message if it was built for a different N than the parameters.
- **Controller and asset models are the source.** Develop them in the Simulink editor. `buildHPP(All=true)` only creates the ones that don't exist yet, from the templates in `buildHPP.m`; existing models are never touched. Regenerating one from its template overwrites all hand edits and needs an explicit `buildHPP(All=true, Overwrite=true, Only="HPPC")` (`Force=true` alone stops with an explanation).
- **Rules for hand edits** (checked by `checkModels`, which runs at the start of `buildHPP` and of a Rapid Accelerator build, as a warning, or an error with `Strict=true`):
  - keep the port names and order of `utilities/modelInterfaces.m` (`HPP.slx` connects by port number; HPPC has 20 inputs);
  - in block parameters that use `par` / `ap`, only `+ - * /`, parentheses, numbers and field access: `^`, `sqrt`, comparisons, `[a b]` or indexing cannot stay tunable in compiled code and break the Rapid Accelerator build. Compute such values in `params/controllerParameters.m` as a new `par` field, or inside a MATLAB Function block (its code is not restricted);
  - every `par` / `ap` field used must exist in `HPP_parameters()`.
  `checkModels()` returns a table with the block path and a suggested fix for each finding.

**Background colours show the role** on every level: light blue = controllers (future DLLs), light green = assets / plants, light grey = interfaces and network. The plant subsystems are divided into areas: bus inputs | plant controller | N assets | outputs to the HPPC and network (all outputs in one column on the right).

**On every level** (top level, subsystems and models) blocks sit level with the ports they connect to, so lines are straight. The plant SOC for logging travels in the BESS measurement bus as `SOC_plant`. Local Goto/From blocks replace lines that would cross or run backwards: blue = set-points, green = network signals, orange = signals from the assets back to the controllers, grey = logging.

Every controller is the same kind of model: inports → one MATLAB Function block `logic` → outports; all `double`, per unit on its own base, fixed sample time `Ts`, tunable parameters in the model argument `par` (= `p.ctrl.<name>.par`). The model workspace holds standalone defaults for `Ts` and `par` from `HPP_parameters()`. The full signal lists are in docs/design.md, section 4.

Communication delays (`p.comm`, typical 20–200 ms) are discrete delays of whole simulation steps in `HPP.slx`. The setting `p.comm.delays` (or the option `Delays` of `runCase` / `runSweep`, `delays` in `main.m`) chooses how they are compiled: `"fixed"` is the fastest, `"variable"` makes the delays tunable between runs up to `p.comm.maxDelay` (0.5 s) for delay sweeps, and `"auto"` (default) picks variable only when the case set changes a delay (for example `comm_delay`). Every measurement path into a controller also has a one-step memory, which avoids algebraic loops.

## Parameters

Everything the models use lives in the struct `p`. Blocks reference fields such as `p.wt.Pn`; there are no other workspace variables. To change a default, edit the component function in `params/`. For interactive work, reload afterwards with `p = HPP_parameters();`.

Asset counts and layout: each plant has `nFeeders` feeders with `nPerFeeder` units; every unit is its own asset instance (converter model and controller) at its own network node. A unit can stand for `nAgg` identical units, and a modelled feeder for `p.net.<type>.cable.nPar` parallel feeders. Default layout (plant sizes 150 / 50 / 30 MW): wind 1 feeder × 2 units of 15 × 5 MW turbines (10 kV, `nPar` = 15), PV 2 feeders × 1 unit of 5 × 5 MW stations (33 kV), one 30 MW / 60 MWh BESS at the 33 kV HPP busbar. A 1 × 1 layout per plant (wind `nAgg` = 30, `nPerFeeder` = 1; PV `nAgg` = 10, `nFeeders` = 1, `nPar` = 2) gives the same results within about 0.15 MW and simulates about 25 % faster. Changing the number of units requires `buildHPP`; collector data are in `networkParameters`.

Network model: the `Network` block holds two models with the same results (nominal P_poc within 1 kW, dip within 0.1 MW), chosen per run without rebuilding: `"nodal"` (nodal solver, fast) and `"simscape"` (Simscape Electrical blocks in frequency-and-time mode, component-wise, much slower: about 40 s of simulation per 60 s case). Choose it with the `network` setting in `main.m`, or `runCase(set, id, Network="nodal")`, `runSweep(set, Network="simscape")`; the default is `p.net.solverType`, set to `"nodal"`.

Run time: **Rapid Accelerator** is the fastest and the default in `main.m` (`mode = "rapid"`; `runCase(..., Mode="rapid")`, `runSweep(set, Mode="rapid")`). The model with its controller and asset models is compiled once into a program with MinGW (`rapidTarget`, about 20–50 s), and every run reuses it with its own `p`: about 1.5–2 s per 60 s case with fixed delays (about 2.2–2.6 s with variable delays), with results identical to normal mode (within 2e-12). All seven case sets (46 cases) run in about 70 s, against about 15 minutes in normal mode with Fast Restart. The target is rebuilt by itself when the layout, time step, delay mode (with fixed delays: the delays; with variable delays: `p.comm.maxDelay`), network model or a model file change; its fingerprint is saved next to it (`hpp_rapid_fingerprint.mat`), so a new MATLAB session reuses it without rebuilding. Normal mode stays for debugging with scopes inside the models. Rapid Accelerator falls back to normal mode (with Fast Restart) with a warning that says why when there is no C compiler, with the Simscape network, when `checkModels` finds block parameters that compiled code cannot use, or when the build fails. A parallel pool does not help with Rapid Accelerator: each run is so short that parsim's overhead dominates (16 cases: 24 s serial, 101 s on 3 workers).

Normal mode and Fast Restart (nominal 60 s case, nodal network). Without Fast Restart every run compiles the model with its referenced controller and asset models, which is most of the time: about 50–100 s per run. With Fast Restart the model stays compiled and every further run only simulates: about 3–16 s per 60 s case with the nodal network (fewer units and more free memory are faster), about 40 s with the Simscape network. Use `runCase(..., FastRestart=true)` (the `fastRestart` setting in `main.m`, on by default) or `runSweep(set, FastRestart=true)` (grid_strength, 3 cases: 25 s in total with the 1 × 1 layout).

Almost all parameters can change between Fast Restart runs without recompiling: controller parameters, set-points, events (dips, frequency steps), grid strength (SCR, X/R, E), cable, transformer and unit data. The nodal network gets its numbers through tunable constants, the Simscape network uses run-time block parameters. The communication delays are tunable too with `p.comm.delays = "variable"` (chosen by itself for case sets that change them). Fixed at compile time are only the layout (units per plant), the time step, the delay mode (with fixed delays also the delays) and the network model; `runCase` recompiles by itself when one of these changes, and `runSweep` with Fast Restart refuses case sets that change them. The top model uses a single-step solver (ode1, single-tasking) and logs every 10 ms (`p.sim.logDecimation`). Accelerator mode (needs a C compiler) would mainly shorten the first compile.

Controller parameters (`p.ctrl`, from `controllerParameters`):

| Controller | Field | `Ts` | Per-unit base |
|---|---|---|---|
| HPPC | `p.ctrl.hppc` (settings from `p.hppc`, `hppcParameters`) | 0.1 s | POC, `p.grid.Pbase` (180 MW) |
| WPPC, SPPC, BESSC | `p.ctrl.wppc`, `.sppc`, `.bessc` | 20 ms | plant rating (150 / 50 / 30 MW) |
| WT, PV, BESS asset controllers | `p.ctrl.wt`, `.pv`, `.bess` | 1 ms | unit rating `nAgg · Pn` (75 / 25 / 30 MW) |

The W↔pu conversions happen in `HPP.slx`, so the logged signals and plots are in W (MW). In PSCAD the same conversions belong on the PSCAD side of the DLLs.

## Case sets

A case set is a function in `scripts/+caseSets/` that returns a table. Each column is a field path in `p` (for example `"grid.Pref"`), each row is one case, and `NaN` means "keep the default". Rows may have names.

| Set | Cases | Built with |
|---|---|---|
| `nominal` | 1: the defaults. **Project default.** | row `nominal` of `handpicked` |
| `handpicked` | `nominal`, `lowRef`, `highRef`, `noBess` | `caseList` (one line per case) |
| `grid_Pref_Pbess` | 9: every combination of 3 Pref × 3 BESS ratings | `caseGrid` |
| `oat_Pref` | 8: Pref and BESS rating varied one at a time | `caseOAT` |
| `grid_strength` | `SCR10` (default), `SCR5`, `SCR3` | `caseList` |
| `wt_frt` | `no dip`, `dip 0.5`, `dip 0.8`, `dip 0.5 SCR3` (150 ms grid voltage dip at 45 s, after the plant has ramped up) | `caseList` |
| `freq_step` | `no event`, `+0.2 Hz (LFSM-O limit)`, `+0.5 Hz LFSM-O`, `-0.5 Hz LFSM-U`, `+0.2 Hz FSM`, `-0.2 Hz FSM`, `+0.5 Hz FSM + LFSM-O`, `+0.2 Hz, decentral`, `-0.2 Hz, decentral` (at 50 s, 70 s runs) | `caseList` |
| `hppc_qv` | Q steps ±30 Mvar, voltage control after a 2 % grid voltage drop (slopes 2 / 4 / 7 %, SCR 10 / 3, mis-set SCR), Q control in the same event, `Vref 1.01`, `PF 0.95 export` / `import` (events at 40 s) | `caseList` |
| `hppc_p` | `Pref 150 MW`, `step -30 MW`, `step +20 MW`, `step +40 MW (limit)`, `step -30 MW, 10 %/min`, `step -30 MW, no ramp` (P_ref step at 40 s, 120 s runs) | `caseList` |
| `bess_soc` | `SOC0 0.5`, `SOC0 0.15`, `at SOCmin`, `SOC0 0.85`, `at SOCmax`, `SOC0 0.5, +20 MW`, `SOC0 0.15, +20 MW` | `caseList` |

To add a set, copy one of these files, rename it and edit it. Nothing else needs to change. Three helpers build the table:

```matlab
% caseList: named cases, one line each, listing only what changes
cases = caseList({
    "nominal",  {}
    "lowRef",   {"grid.Pref", 100e6}
    "small",    {"grid.Pref", 100e6, "bess.Pmax", 15e6}
});

% caseGrid: every combination
cases = caseGrid("grid.Pref", [100 150 200]*1e6, "pv.Prated", [25 50]*1e6);

% caseOAT: one parameter at a time
cases = caseOAT("grid.Pref", [50 100 200]*1e6, "bess.Pmax", [0 60]*1e6);
```

In `handpicked`, adding a case is adding one line; the other cases never need editing.

## Running

| Goal | Command |
|---|---|
| Nominal case | `runCase()` |
| One case by name or number | `runCase("handpicked", "noBess")`, `runCase("grid_Pref_Pbess", 4)` |
| Quick check, no file written | `runCase("oat_Pref", 2, Save=false)` |
| Fastest: compiled once, ~1.5 s per case | `runCase(..., Mode="rapid")`, `runSweep(set, Mode="rapid")` |
| Normal mode, rerun without compiling | `runCase(..., FastRestart=true)`, `runSweep(set, FastRestart=true)` |
| Simscape network instead of nodal | `runCase(..., Network="simscape")`, `runSweep(set, Network="simscape")` |
| All cases of a set, serial | `runSweep("oat_Pref")` |
| All cases with a local pool | `runSweep("oat_Pref", UseParallel=true)`, then `delete(gcp('nocreate'))` |
| Debug a case in the Simulink editor | `c = defineCases("handpicked"); p = applyCase(HPP_parameters(), c("noBess", :));` then open `HPP.slx` and press Run |

`runCase` saves `results/<set>/case_NNN.mat` with `out`, `p` and `caseInfo`. `runSweep` saves `results/<set>/sweep.mat` with `out`, `cases` and `setName`. A rerun overwrites the file, so copy results you want to keep.

Read signals with `out.yout.get("SOC").Values`. The logged signals:

| Signal | Unit | Meaning |
|---|---|---|
| `P_poc`, `Q_poc` | W, var | delivered into the grid at the POC |
| `V_poc`, `V_bus` | pu | POC voltage, 33 kV busbar voltage |
| `P_wpp`, `P_spp`, `P_bess`, `Q_wpp`, `Q_spp`, `Q_bess` | W, var | each plant's output into the 33 kV busbar |
| `P_bess_set` | W | HPPC set-point to the BESS plant |
| `SOC` | – | plant SOC (share-weighted mean of the assets) |

Run time: see Parameters (Rapid Accelerator, Fast Restart). Needs the MinGW C compiler (installed); block parameters that use controller or asset parameters are kept to simple arithmetic (derived values such as tan(phi) and mode flags are computed in `controllerParameters`), so they stay tunable in compiled code.

## Looking at results

```matlab
plotResults("handpicked")                    % all saved cases of a set, one line per case
plotResults("handpicked", "noBess")          % one saved case
plotResults(out, Cases=defineCases("oat_Pref"))   % straight from runSweep, nothing saved
plotResults(..., Signals=["P_poc","SOC"])    % choose signals
plotResults(..., Theme="light")              % light figure for reports
plotResults(..., NewFigure=true)             % keep the old figure, open another
plotAllResults(Purpose="report")             % report figures (reportFigures.m) -> results/figures/report/
plotAllResults()                             % debug figures of every saved set -> results/figures/debug/
plotAllResults("wt_frt", Mode="showAndSave") % ... figures open as well; Mode="show": no files

T = summarizeResults("grid_Pref_Pbess")      % final, min and max per signal and case
[out, cases] = loadResults("handpicked")     % the saved runs, for your own analysis
```

Plots have one panel per signal on a shared time axis, powers in MW, and lines labelled by case name or by the values the case changes (`Pref=100 MW, Pmax=0 MW`). Line colours come from the DTU design guide (`dtuColors`: DTU blue, corporate red, green, orange, purple, navy, red; lighter DTU tints on a dark figure); the background follows the MATLAB theme. Figures are always docked, and plotting the same set again redraws its existing figure (one figure per title, by default the set name) instead of opening a new one. `loadResults` uses `results/<set>/sweep.mat` if it exists, otherwise all `case_NNN.mat` files of the set. For interactive browsing of a single run, Simulink's Simulation Data Inspector also works: `Simulink.sdi.view`.

`plotAllResults` has two purposes:
- **report:** one small figure per point a case set makes, defined in `scripts/reportFigures.m`. Each entry gives the cases, the signals per axis (at most two or three axes), the time window (fault cases zoomed on the fault) and a one-line statement of what the figure shows. Figures are 8.8 cm wide (one column), 8 pt Times, legend inside the top axis, references (P_ref, Q_ref, available power) dashed; saved as vector PDF for LaTeX (`\includegraphics` at natural size) plus a PNG preview. Add or change a figure by editing `reportFigures.m`.
- **debug:** every logged signal of every case of a set in one large figure (P, Q, V, f, plant P with availability, BESS P with set-point, SOC, plant Q), full time plus a zoom on the event (`<set>_zoom`); PNG and `.fig`.

Logged signals (`out.yout`): `P_poc`, `Q_poc`, `V_poc`, `V_bus`, `P_ref`, `Q_ref`, `f`, `P_wpp`, `P_spp`, `P_bess`, `P_bess_set`, `P_avail_wpp`, `P_avail_spp`, `Q_wpp`, `Q_spp`, `Q_bess`, `SOC`.

Serial is the default for `runSweep`. Each pool worker needs about 1 GB of RAM, and on a 16 GB laptop starting a pool next to the desktop session has crashed MATLAB.

## HPC (LSF)

From the project root on the cluster:

```bash
hpc/submit.sh grid_Pref_Pbess
```

This submits one job per case, each running `runCase(set, i)`. The script counts the cases itself; pass the count as a second argument to skip that MATLAB call. Logs go to `hpc/logs/`. Adjust the queue, memory, walltime and MATLAB module in `hpc/job.lsf` to the cluster. Not yet tested on the cluster.

## Conventions

- Battery power is positive when discharging (exporting to the grid).
- Powers are in W, energy in J, state of charge and availability in per unit.
- Every controller sample time must be an integer multiple of `p.sim.Ts`; `controllerParameters` checks this.

## Status and next steps

- Stages 1 (structure), 2 (network), 3 (IEC Type 4A wind turbine, fault-ride-through case set `wt_frt`) and 4 (WECC REEC_B / REEC_C + REGC_A for PV and BESS, closed-loop asset Q control, REPC_A plant controllers; case sets `bess_soc`, `freq_step`) are done. All controllers are block diagrams in `models/ctrl/`; parameter values (`p.wt.iec`, `p.pv.wecc`, `p.bess.wecc`, `p.pc`, `p.hppc`) are typical values to be checked against the standards.
- Stage 5 started: **central control** (default). The HPPC closes the P loop at the POC (PI with the target fed forward, a reference filter `Tref`, frozen during voltage dips) and gives the frequency response of the whole plant (LFSM / FSM after the grid code, below); it dispatches wind and PV at available power and lets the BESS balance, curtailing wind and PV only when the BESS cannot absorb more. The plant controllers pass their P set-points on (`p.pc.<plant>.Frqflag` = 0: no local droop, no plant P loop); their Q loops stay closed. Nominal: P_poc 150.00 MW for P_ref 150 MW (146.5 MW open loop). The stage-4 setup (open-loop HPPC, droop in every plant controller) is kept as the `decentral` cases in `freq_step`.
- Stage 5, Q / V: the HPPC closes a Q loop at the POC (default, tracks the TSO Q_ref: Q_poc 0.00 Mvar instead of −11.4 Mvar open loop) or a voltage loop (`p.hppc.RefFlag` = 1, `Vref`, slope `Vslope`), over the plants' own Q loops, and splits its Q order over the plants by rating; limits ±0.33 pu (60 Mvar), frozen in a dip like the P loop. Q_ref steps of ±30 Mvar settle in about 0.65 s; their 6–10 Mvar overshoot comes mostly from the plant and asset Q loops. Voltage control has a slope (below), so V_poc is held on the Q-V characteristic rather than at exactly Vref.
- Stage 5, grid code (Energinet DK1: Danish RfG requirements for power park modules type D, TR 3.3.1 for the BESS): ramp rate constraint 20 % Pn/min = 36 MW/min (`p.hppc.rampUp` / `rampDn`, range 1–20 %/min) on the set-point and availability changes, not on the frequency response; LFSM-O 50.2 Hz and LFSM-U 49.8 Hz with 5 % droop (always on); FSM (`p.hppc.FSMflag`, 5 %, 10 mHz deadband, ±10 % Pn, BESS reserve) when delivering FCR; voltage control with slope (`Vslope` 4 %, range 2–7 %; 90 % within 0.6 s, requirement 1 s); power factor control (`RefFlag` = 2); SOC-aware BESS limits (derated over 0.1 above SOCmin / below SOCmax). Checks in docs/design.md, section 8.
- Stage 5, voltage control as a cascade (`p.hppc.Vlocal` = 1, default): in voltage control the plant controllers control the 33 kV busbar voltage themselves on a V-Q droop line (the POC slope minus the 33/132 kV transformer reactance), and the HPPC only trims their Q offsets slowly (about 3 s) so V and Q at the POC lie on the required slope. Each control level is at least 3 times slower than the one below (asset Q 0.11 s, plant 0.6–1.1 s, HPPC 3–5.5 s; `controllerParameters` warns otherwise). The HPPC holds the POC Q limit (±59.4 Mvar) by capping its voltage error, and has anti-windup over the plant limits: the plant controllers report `Q_sat` (Q order at its limit) and the HPPC holds its Q loop when all plants are saturated (`QawFlag`). Voltage control after a 2 % grid drop: 90 % within 0.4–0.6 s, settled within 0.5 s, for slopes 2–7 % and SCR 3–10. Next: V_ref / PF from the TSO, Q capability, SOC restoration.
- Start-up is not initialised in steady state yet: during the first fraction of a second the controllers see zero measurements and the network sees no injection.
- The HPPC derates the BESS limits near SOCmin / SOCmax, but does not restore SOC towards a target yet.
- The `"noBattery"` variant bug is fixed: derived parameters are now computed after the variant.
- Later: code generation of every controller and IEEE/CIGRE DLLs for PSCAD. MATLAB Coder, Embedded Coder and MinGW are installed (2026-11-19); Simulink Coder is being added.
